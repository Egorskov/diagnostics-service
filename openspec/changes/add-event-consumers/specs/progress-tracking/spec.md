# Spec Delta

## Purpose

Как входящие события меняют состояние ученика: путь и задания, статус и время по заданиям, списанное время и запуски песочницы (SPEC §4, §5). На этом состоянии строятся метрики SPEC §6 и сигналы §7.

## ADDED Requirements

### Requirement: Назначение пути
При `path.assigned` сервис SHALL сохранить связь ученика с путём (`student_path`) и привести задания пути (`path_task`) в точное соответствие со снапшотом: снапшот полный и заменяет предыдущий. Для каждого задания снапшота без прогресса у этого ученика MUST появиться прогресс в статусе `not_started`.

#### Scenario: Первое назначение
- **WHEN** приходит `path.assigned` с тремя заданиями
- **THEN** сохранены ментор, `started_at`, `weekly_goal_minutes`, у пути три задания с этапом, оценкой и позицией, а у ученика три прогресса `not_started` с `active_minutes` = 0 и `failed_runs` = 0

#### Scenario: Повторное назначение с другим составом
- **WHEN** приходит новый `path.assigned` того же ученика и пути, где одного задания больше нет, одно добавлено, а у третьего изменена оценка
- **THEN** задания пути совпадают с новым снапшотом, для добавленного задания появился прогресс `not_started`

#### Scenario: Прогресс не сбрасывается
- **WHEN** новый снапшот приходит, когда у ученика уже есть прогресс по заданиям, в том числе по заданию, убранному из пути
- **THEN** статус, время и счётчики существующих прогрессов не изменились, и ни один прогресс не удалён

#### Scenario: Путь без заданий
- **WHEN** приходит `path.assigned` с пустым `tasks`
- **THEN** связь ученика с путём сохранена, заданий у пути нет, событие считается обработанным

### Requirement: Начало задания
При `task.started` сервис SHALL перевести прогресс ученика по заданию из `not_started` в `in_progress` и сохранить `started_at` = `occurred_at` события.

#### Scenario: Обычный старт
- **WHEN** приходит `task.started` по заданию в статусе `not_started`
- **THEN** статус `in_progress`, `started_at` равен `occurred_at` события

### Requirement: Завершение задания
При `task.completed` сервис SHALL перевести прогресс в `completed` и сохранить `completed_at` = `occurred_at` события.

#### Scenario: Обычное завершение
- **WHEN** приходит `task.completed` по заданию в статусе `in_progress`
- **THEN** статус `completed`, `completed_at` равен `occurred_at` события, `started_at` не изменился

### Requirement: Устойчивость прогресса к порядку событий
Результат `task.started` и `task.completed` MUST NOT зависеть от порядка их доставки: статус не откатывается назад, а `started_at` и `completed_at` хранят самый ранний момент из пришедших событий. Ни одно из этих событий MUST NOT требовать предварительного `path.assigned`: у них есть свой `path_id`.

#### Scenario: Завершение раньше старта
- **WHEN** `task.completed` пришло раньше `task.started` того же задания
- **THEN** после обоих событий статус `completed`, заполнены и `started_at`, и `completed_at`

#### Scenario: Завершение без старта
- **WHEN** приходит `task.completed`, а `task.started` не приходил
- **THEN** статус `completed`, `completed_at` заполнен, `started_at` пуст

#### Scenario: Повторное завершение с другим event_id
- **WHEN** приходит второй `task.completed` того же задания с другим `event_id` и более поздним `occurred_at`
- **THEN** `completed_at` остаётся прежним

#### Scenario: Событие раньше назначения пути
- **WHEN** `task.started` приходит раньше `path.assigned`
- **THEN** прогресс создан с `path_id` из события, а последующий `path.assigned` его не сбрасывает

### Requirement: Списание времени
При `time.logged` сервис SHALL добавить запись в `time_log` с учеником, необязательным заданием, категорией, минутами, днём списания и `event_id` исходного события. Записи MUST суммироваться, а не заменять друг друга: контракт описывает каждое списание как отдельный факт.

#### Scenario: Списание по заданию
- **WHEN** приходит `time.logged` с `task_id`
- **THEN** появилась запись с этим заданием, `logged_for_date` из события и `source_event_id` = `event_id`

#### Scenario: Списание без задания
- **WHEN** приходит `time.logged` без `task_id`
- **THEN** появилась запись с пустым заданием

#### Scenario: Два списания за один день
- **WHEN** приходят два `time.logged` с разными `event_id` на одного ученика, день и категорию
- **THEN** в `time_log` две записи

### Requirement: Запуски песочницы
При `sandbox.run` сервис SHALL сохранить запуск в `sandbox_run` и увеличить `failed_runs` прогресса на 1, если результат не `passed` (то есть `failed` или `error`). Статус прогресса MUST NOT меняться: начало задания определяет только `task.started`.

#### Scenario: Неудачный запуск
- **WHEN** приходит `sandbox.run` с результатом `failed` и `error_type`
- **THEN** запуск сохранён с `error_type` и `occurred_at`, `failed_runs` увеличился на 1

#### Scenario: Ошибка запуска
- **WHEN** приходит `sandbox.run` с результатом `error`
- **THEN** `failed_runs` увеличился на 1

#### Scenario: Успешный запуск
- **WHEN** приходит `sandbox.run` с результатом `passed`
- **THEN** запуск сохранён, `failed_runs` не изменился

### Requirement: Запуск идентифицируется по run_id
Повторное событие с уже сохранённым `run_id`, но новым `event_id`, MUST NOT менять состояние: один запуск учитывается один раз.

#### Scenario: Тот же запуск с другим event_id
- **WHEN** приходит `sandbox.run` с уже сохранённым `run_id` и новым `event_id`
- **THEN** в `sandbox_run` одна запись, `failed_runs` не изменился, событие считается обработанным

### Requirement: Событие без необходимого контекста не теряется
`sandbox.run` не содержит `path_id`, поэтому прогресс нельзя создать из него самого. Если прогресса по заданию нет, сервис MUST NOT применять событие частично: обработка считается ошибкой и идёт по общей схеме ретраев и failure transport (SPEC §9).

#### Scenario: Запуск по неизвестному заданию
- **WHEN** приходит `sandbox.run` по заданию, для которого у ученика нет прогресса
- **THEN** запись в `sandbox_run` не появилась, событие не отмечено обработанным и будет повторено

#### Scenario: Контекст появился во время ретраев
- **WHEN** `path.assigned` с этим заданием обработан раньше следующей попытки
- **THEN** повтор проходит, запуск сохранён и учтён

#### Scenario: Ретраи исчерпаны
- **WHEN** прогресс так и не появился за все попытки
- **THEN** событие находится в failure transport, и его можно повторить вручную после появления контекста

### Requirement: Heartbeat принимается как точка активности
`activity.heartbeat` SHALL обрабатываться успешно и подтверждаться брокеру, не попадая в failure transport, независимо от наличия пути и прогресса. Данные прогресса heartbeat MUST NOT менять: активное время считается на шаге 4 MVP (SPEC §6.1).

#### Scenario: Heartbeat без задания
- **WHEN** приходит `activity.heartbeat` без `task_id`
- **THEN** событие подтверждено, таблицы прогресса не изменились

#### Scenario: Heartbeat по неизвестному заданию
- **WHEN** приходит `activity.heartbeat` с `task_id`, для которого нет прогресса
- **THEN** событие подтверждено, прогресс не создан
