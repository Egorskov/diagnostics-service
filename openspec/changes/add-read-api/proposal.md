# Proposal

## Why

Шаг 7 MVP (CLAUDE.md «Текущий скоуп», п. 7; SPEC §8, §10). Диагностика уже считает прогресс и публикует сигналы, но ни ученик, ни ментор не могут увидеть картину целиком. Без Read-API у дашбордов нет данных: ученик не знает, где он относительно плана, а ментор — кто из учеников отстаёт (SPEC §1).

## What Changes

- `GET /api/v1/students/{id}/summary` — сводка ученика по текущему пути в форме примера SPEC §8:
  - EV/PV/AC, SPI/CPI, плановая и прогнозная даты, отставание — из готового `PathMetrics` (шаг 5);
  - неделя: недельная цель, списано, активно, активные дни;
  - серия активных дней (регулярность, SPEC §6.2);
  - баланс списанного времени по категориям `theory` / `practice` / `interview`;
  - активные сигналы из `signal_state`.
- `GET /api/v1/mentor/students` — ученики, у которых текущий путь ведёт этот ментор, с основными метриками, отсортированные по риску (design, решение 7).
- Аутентификация (SPEC §8). Запрос несёт `Authorization: Bearer <JWT>`, из payload читаются `sub` и `role` (`student` | `mentor`). На MVP подпись не проверяется — это заглушечный authenticator, который CLAUDE.md разрешает; позже его заменит проверка публичным ключом Auth (ADR 0006).
- Права доступа (SPEC §8). Ученик видит только себя. Ментор видит учеников, чей текущий путь ведёт он (`student_path.mentor_id`). Ответы на ошибки: 401 — нет токена или он невалиден, 403 — чужой ученик или не та роль, 404 — у ученика нет пути.
- Новая зависимость `symfony/security-bundle`: firewall, authenticator и voter — стандартные точки расширения Symfony. Замена заглушки на настоящий JWT коснётся только authenticator (design, решение 2).

Решения, о которых SPEC молчит, зафиксированы в design: граница недели, что считать активным днём и серией, период баланса, порядок сортировки по риску, формат чисел и дат. `SPEC.md` и `asyncapi.yaml` не меняются.

Вне скоупа:
- Остальные эндпоинты §8: `timeline`, `tasks`, `mentor/materials`, `mentor/thresholds` — бэклог SPEC §10.
- Проверка подписи JWT публичным ключом Auth, справочник ролей из `user.registered`.
- «Расхождение» (списано / активно, SPEC §6.2) — его нет в примере summary.
- Пагинация и фильтры у `mentor/students`.
- Таймзона ученика: даты и неделя считаются в Europe/Belgrade (SPEC §9).

## Capabilities

### New Capabilities
- `api-auth`: аутентификация Read-API по JWT (на MVP — заглушка без проверки подписи) и права доступа «ученик — себя, ментор — своих» (SPEC §8).
- `student-summary`: сводка ученика — метрики пути, неделя, серия, баланс, активные сигналы (SPEC §6.2, §8).
- `mentor-students`: список учеников ментора с метриками и сортировкой по риску (SPEC §8).

### Modified Capabilities

Нет. `path-metrics` используется как есть, а правила сигналов не меняются: API только читает `signal_state`.

## Impact

- Новый слой `src/UI/Http/`: контроллеры `/api/v1`, authenticator и voter.
- Новые read-модели на DBAL в Infrastructure. Новых таблиц и миграций нет.
- Новый расчёт в Domain: неделя, серия и баланс. Юнит-тесты на табличных примерах.
- Зависимость `symfony/security-bundle`, конфиг `config/packages/security.yaml`.
- Новый ADR `docs/adr/0006-api-auth-stub.md`.
- HTTP проверяется через nginx (`localhost:8080`). Функциональные тесты вызывают `kernel->handle()` и не требуют новой dev-зависимости (design, решение 9).
