# api-auth Specification

## Purpose

Кто может обращаться к Read-API `/api/v1` и что ему видно (SPEC §8). Пользователей ведёт сервис Auth (SPEC §2), а Диагностика доверяет его JWT. На MVP подпись не проверяется: это заглушка до появления публичного ключа Auth.

## Requirements

### Requirement: Токен в каждом запросе
Каждый запрос к `/api/v1` SHALL нести заголовок `Authorization: Bearer <JWT>`. Из payload токена SHALL читаться `sub` — идентификатор пользователя, и `role` — `student` или `mentor`. На запрос без токена, с токеном не из трёх частей, с payload не в JSON, без `sub`, с другой `role` или с истёкшим `exp` сервис MUST отвечать 401 и не раскрывать данных.

#### Scenario: Нет заголовка
- **WHEN** запрос `GET /api/v1/mentor/students` без `Authorization`
- **THEN** ответ 401 с телом `{"error": "unauthorized"}`

#### Scenario: Неизвестная роль
- **WHEN** в payload токена `role` = `admin`
- **THEN** ответ 401

#### Scenario: Истёкший токен
- **WHEN** `exp` токена раньше текущего момента
- **THEN** ответ 401

#### Scenario: Токен без exp
- **WHEN** в payload есть `sub` и `role`, а `exp` нет
- **THEN** запрос аутентифицирован

### Requirement: Подпись на MVP не проверяется
На MVP сервис MUST NOT проверять подпись JWT и алгоритм из заголовка токена: проверка публичным ключом Auth отложена (SPEC §8; CLAUDE.md, шаг 7). Это ограничение SHALL быть явно записано, чтобы заглушку не приняли за настоящую аутентификацию.

#### Scenario: Произвольная подпись
- **WHEN** у токена с валидным payload в третьей части произвольная строка
- **THEN** запрос аутентифицирован

### Requirement: Ученик видит только себя
Пользователь с ролью `student` SHALL получать данные только по своему `student_id`, равному `sub`. На запрос о другом ученике или к эндпоинтам ментора MUST отвечать 403 с телом `{"error": "forbidden"}` (SPEC §8).

#### Scenario: Своя сводка
- **WHEN** ученик `s1` запрашивает `GET /api/v1/students/s1/summary`
- **THEN** ответ 200

#### Scenario: Чужая сводка
- **WHEN** ученик `s1` запрашивает сводку ученика `s2`
- **THEN** ответ 403

#### Scenario: Список ментора
- **WHEN** ученик запрашивает `GET /api/v1/mentor/students`
- **THEN** ответ 403

### Requirement: Ментор видит своих учеников
Пользователь с ролью `mentor` SHALL получать данные ученика, если `mentor_id` текущего пути ученика равен `sub`. Текущий путь — с самым поздним `started_at`, а при равенстве — с наибольшим `path_id`, как у правил сигналов. На ученика с другим ментором текущего пути и на ученика без пути MUST отвечать 403.

#### Scenario: Свой ученик
- **WHEN** ментор `m1` запрашивает сводку ученика, текущий путь которого ведёт `m1`
- **THEN** ответ 200

#### Scenario: Ученик ушёл к другому ментору
- **WHEN** у ученика пути от 2026-09-01 с ментором `m1` и от 2026-10-01 с ментором `m2`
- **THEN** ментору `m1` отвечают 403, ментору `m2` — 200
