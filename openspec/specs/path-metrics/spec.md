# path-metrics Specification

## Purpose

Метрики прогресса ученика по пути: освоено, план, факт, темп, эффективность, плановая и прогнозная даты завершения (SPEC §3, §6.2). На них строятся `GET /students/{id}/summary` и сортировка учеников ментора по риску.

## Requirements

### Requirement: Освоено
Метрики SHALL считаться по одному пути ученика в заданный момент «сейчас», в целых минутах (SPEC §6.2). `EV` SHALL равняться сумме `estimate_minutes` заданий текущего состава пути в статусе `completed`.

#### Scenario: Пример из SPEC §8
- **WHEN** закрыты задания пути на 2700 минут из 6000
- **THEN** `EV` = 2700

#### Scenario: Начатое задание не освоено
- **WHEN** задание пути в статусе `in_progress`
- **THEN** его оценка не входит в `EV`

### Requirement: План
`PV` SHALL равняться `min(Σ estimate_minutes всех заданий пути, weekly_goal_minutes × недель с начала)` (SPEC §6.2). Недели с начала — дробное число `(сейчас − started_at) / 7 суток`, до `started_at` — 0. Дробная часть минут отбрасывается.

#### Scenario: Пример из SPEC §8
- **WHEN** сумма оценок 6000, `weekly_goal_minutes` = 1500, с начала прошло 16,8 суток
- **THEN** `PV` = 3600

#### Scenario: План ограничен объёмом пути
- **WHEN** сумма оценок 3000, `weekly_goal_minutes` = 1500, с начала прошло 3 недели
- **THEN** `PV` = 3000

#### Scenario: Неполная минута плана
- **WHEN** `weekly_goal_minutes` = 1000, с начала прошли сутки
- **THEN** `PV` = 142

#### Scenario: Путь ещё не начался
- **WHEN** «сейчас» раньше `started_at`
- **THEN** `PV` = 0

### Requirement: Факт
`AC` SHALL равняться сумме `time_log.minutes` записей, у которых `task_id` входит в текущий состав пути (SPEC §6.2). Списания без задания и по заданиям вне пути MUST NOT учитываться.

#### Scenario: Пример из SPEC §8
- **WHEN** по заданиям пути списано 3300 минут
- **THEN** `AC` = 3300

#### Scenario: Списание без задания и по чужому заданию
- **WHEN** у ученика есть списание без `task_id` и списание по заданию, которого нет в пути
- **THEN** ни одно из них не входит в `AC`

### Requirement: Темп и эффективность
`SPI` SHALL равняться `EV / PV`, `CPI` — `EV / AC` без округления (SPEC §6.2); округление — забота представления. При `PV` = 0 `SPI` MUST NOT считаться, при `AC` = 0 не считается `CPI`.

#### Scenario: Пример из SPEC §8
- **WHEN** `EV` = 2700, `PV` = 3600, `AC` = 3300
- **THEN** `SPI` = 0,75, `CPI` ≈ 0,818 (0,82 после округления до сотых)

#### Scenario: Нулевой план
- **WHEN** `PV` = 0
- **THEN** `SPI` не посчитан, остальные метрики посчитаны

#### Scenario: Ничего не списано
- **WHEN** `AC` = 0
- **THEN** `CPI` не посчитан

### Requirement: Календарные даты
Даты завершения SHALL считаться календарными днями в Europe/Belgrade: «сегодня» — дата момента «сейчас» в этой зоне, дата начала пути — дата `started_at` в ней же (SPEC §9: таймзона ученика — бэклог).

#### Scenario: Полночь по Белграду наступила раньше, чем по UTC
- **WHEN** «сейчас» — 2026-11-02T23:30:00Z
- **THEN** «сегодня» — 2026-11-03

### Requirement: Плановая дата завершения
Плановая дата SHALL равняться дате начала пути плюс `Σ estimate_minutes / weekly_goal_minutes` недель, переведённых в дни с округлением вверх (SPEC §6.2). При `weekly_goal_minutes` ≤ 0 плановая дата MUST NOT считаться.

#### Scenario: Ровно четыре недели
- **WHEN** путь начат 2026-10-01, сумма оценок 6000, `weekly_goal_minutes` = 1500
- **THEN** плановая дата — 2026-10-29

#### Scenario: Неполный день
- **WHEN** путь начат 2026-10-01, сумма оценок 6100, `weekly_goal_minutes` = 1500
- **THEN** плановая дата — 2026-10-30

#### Scenario: Нулевая цель
- **WHEN** `weekly_goal_minutes` = 0
- **THEN** плановая дата и отставание не посчитаны, `PV` = 0

### Requirement: Прогноз завершения
Прогноз SHALL равняться «сегодня» плюс `(Σ estimate_minutes − EV) / темп` недель, переведённых в дни с округлением вверх (SPEC §6.2). Темп — сумма оценок заданий, закрытых за последние 4 недели до «сейчас», делённая на число недель окна: 4, а если путь начат меньше 4 недель назад — на число недель с начала, но не меньше 1.

Если все задания пути закрыты, прогноз MUST равняться дате последнего завершения. Если остались незакрытые задания, а темп равен 0, прогноз MUST NOT считаться.

#### Scenario: Полное окно
- **WHEN** путь начат 5 недель назад, осталось 3300 минут, за последние 4 недели закрыто заданий на 1200 минут
- **THEN** темп 300 минут в неделю, прогноз — сегодня + 77 дней

#### Scenario: Задание закрыто раньше окна
- **WHEN** задание закрыто 4 недели и 1 день назад
- **THEN** его оценка входит в `EV`, но не в темп

#### Scenario: Путь начат две недели назад
- **WHEN** с начала прошло 2 недели и закрыто заданий на 600 минут
- **THEN** темп 300 минут в неделю

#### Scenario: Путь начат два дня назад
- **WHEN** с начала прошло 2 дня и закрыто заданий на 300 минут
- **THEN** темп 300 минут в неделю, а не 1050

#### Scenario: Остаток не делится на дни ровно
- **WHEN** осталось 100 минут при темпе 300 минут в неделю
- **THEN** прогноз — сегодня + 3 дня

#### Scenario: Ничего не закрыто за 4 недели
- **WHEN** остались незакрытые задания и за последние 4 недели не закрыто ни одного
- **THEN** прогноз и отставание не посчитаны

#### Scenario: Путь пройден
- **WHEN** все задания пути закрыты, последнее — 2026-10-20
- **THEN** прогноз — 2026-10-20 независимо от «сегодня»

### Requirement: Отставание
Отставание SHALL равняться разности прогноза и плановой даты в днях (SPEC §6.2). Отрицательное значение означает опережение плана. Если не посчитан прогноз или плановая дата, отставание MUST NOT считаться.

#### Scenario: Отстаёт
- **WHEN** прогноз 2026-11-20, плановая дата 2026-10-29
- **THEN** отставание 22 дня

#### Scenario: Опережает
- **WHEN** прогноз 2026-10-25, плановая дата 2026-10-29
- **THEN** отставание −4 дня
